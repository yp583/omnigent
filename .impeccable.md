## Design Context

### Users

Software developers supervising several long-running coding agents from a desktop client connected to a cloud Omnigent server. They need to scan live state, enter any child transcript, steer the right agent, and track the pull requests produced by a session tree without losing their place.

### Brand Personality

Calm, operational, precise. The interface should feel like a dependable control surface: information-dense without being noisy, responsive without being animated for its own sake, and explicit about which live agent or production session an action targets.

### Aesthetic Direction

Refined developer tooling inspired by the compact hierarchy of Claude Code and the restrained PR treatment in Codex. Preserve Omnigent's existing light and dark themes, warm neutral surfaces, native typography, compact spacing, and status palette. Avoid glow, gradients, ornamental dashboards, oversized cards, or decorative metrics. Status color is semantic and sparingly used.

### Design Principles

1. Make active work, blocked work, and the current command target legible at a glance.
2. Keep navigation spatially stable; streaming and activity must not reorder or jump the interface.
3. Prefer compact rows, progressive disclosure, and one persistent operational rail over modal workflows.
4. Keep controls keyboard-accessible, high-contrast, and understandable without relying on color alone.
5. Use motion only to explain state transitions, respect reduced-motion preferences, and protect scroll performance.
